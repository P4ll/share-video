# Share Video

Вставьте ссылку на видео и создайте комнату. Для каждого зрителя нажмите «Создать приглашение», затем рядом с «Гость 1», «Гость 2» и так далее — «Скопировать ссылку». Короткий адрес `/i/…` открывает комнату от имени этого гостя. Если он перешлёт ссылку, получатель войдёт с теми же правами. Приглашение действует, пока существует комната.

По умолчанию гости могут только смотреть. Флажок «Может управлять видео» рядом с каждым гостем включает или отключает общие Play, Pause и перемотку сразу, без нового приглашения. Воспроизведение и пауза работают через кнопки самого плеера, в том числе в полном экране. Только ведущий может менять источник, создавать приглашения и управлять правами. Полный экран, громкость и субтитры — личные настройки.

Сервер синхронизирует только состояние комнаты. Браузеры загружают видео напрямую из YouTube или с сервера медиафайлов. Здесь нет проксирования видео, извлечения потоков со страниц, ретрансляции и WebRTC.

## Локальный запуск

Из корня репозитория, с установленным Docker:

```sh
docker build -t share-video .
docker run --rm -p 127.0.0.1:8080:8080 share-video
```

Откройте <http://localhost:8080>. Приглашение с `localhost` работает только на этом компьютере; для просмотра с других устройств используйте публичный адрес.

Для разработки без Docker установите Node.js 24 и Rust 1.93 или новее. В одном терминале запустите сервер из корня репозитория:

```sh
cargo run --locked --manifest-path server/Cargo.toml
```

В другом запустите Vite:

```sh
cd web
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно <http://localhost:5173>). Он проксирует API и WebSocket на `127.0.0.1:8080`.

Проверки из корня:

```sh
cargo test --locked --manifest-path server/Cargo.toml
npm --prefix web test  # после npm ci в web/
```

## Публичное развёртывание

### `watch.avgtree.online` — автоматическая выкладка

Пуш в `main` запускает [Deploy Share Video](.github/workflows/deploy.yml). GitHub-hosted runner проверяет Rust и TypeScript и после успешных тестов двигает служебную ветку `deploy/production` на проверенный коммит. Не пушьте в неё вручную. Постоянных ключей GitHub на VPS нет.

`share-video-release.timer` на VPS собирает `share-video:<полный SHA>`, только когда `main` и `deploy/production` указывают на один коммит. Caddy публикует текущий SHA по `/_revision`; workflow сверяет его и `/api/health`. Если контейнер не проходит локальную проверку здоровья, скрипт возвращает предыдущий образ.

CI обновляет только образ приложения. Изменения файлов из [`deploy/`](deploy/) нужно устанавливать на VPS отдельно. Старые образы и кеш сборки автоматически не удаляются. После отката таймер не перезапускает тот же сломанный коммит; после устранения причины администратор может удалить `.failed-revision` в `/opt/share-video` и повторить запуск.

Проверка на VPS от администратора:

```sh
cd /opt/share-video
cat state/revision
systemctl status share-video-release.timer
journalctl -u share-video-release.service -n 60
docker compose ps
docker compose logs --tail=100 app caddy
```

### Другой сервер — ручная установка

На сервере нужны Docker с Compose V2 и доменное имя. Направьте запись DNS `A` на публичный IPv4 сервера; добавляйте `AAAA` только при рабочем публичном IPv6. Откройте входящие TCP-порты 80 и 443 в настройках провайдера и файрволе. Если сервер за NAT, пробросьте оба порта на него.

В корне репозитория создайте или обновите файл `.env`, указав своё имя хоста (без `https://`, порта и пути):

```dotenv
DOMAIN=watch.example.com
```

Запустите сервисы:

```sh
docker compose up -d --build
```

Caddy получит TLS-сертификат и будет перенаправлять HTTP на HTTPS; порт приложения 8080 наружу не публикуется. Откройте `https://watch.example.com` и для проверки создайте комнату, затем откройте приглашение в другом браузере. Проверить доступность сервера и посмотреть журналы можно так:

```sh
curl -fsS https://watch.example.com/api/health
docker compose logs --tail=100 app caddy
```

Для обновления повторите `docker compose up -d --build` после обновления исходников. Комнаты находятся в памяти и теряются при перезапуске приложения; старые приглашения перестанут работать. Сертификаты Caddy хранятся в томе `caddy_data`.

## Источники видео

- **YouTube:** подходят ссылки на видео, которое можно открыть во встроенном плеере. Ограничения на встраивание, регион или аккаунт сохраняются.
- **MP4 и HLS VOD:** используйте прямые ссылки с расширением `.mp4` или `.m3u8` по HTTPS. HTTP допускается для loopback при локальной разработке. Каждый зритель должен иметь доступ к исходному адресу и поддерживаемым браузером кодекам. Для HLS через `hls.js` сервер источника должен разрешать CORS с адреса приложения для плейлистов, сегментов и, при наличии, ключей. Для перемотки MP4 источник должен корректно обслуживать запросы диапазонов байтов.
- Приложение не обходит DRM, авторизацию, запреты встраивания и другие ограничения источника. Синхронизация прямого эфира не поддерживается. Используйте только источники, которыми вам разрешено делиться.
