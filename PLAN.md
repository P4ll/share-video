# Share Video — совместный просмотр без видеопрокси

Ведущий вставляет ссылку и делится приватным приглашением. Участники смотрят одно видео на компьютере или телефоне. Каждый браузер получает видео от исходного сервиса; Rust-сервер синхронизирует только состояние комнаты.

## Объём

- YouTube — официальный встроенный плеер. Поддерживаем ссылки `watch`, `youtu.be`, `shorts`, `live`, `embed` с валидным ID. Источник возвращается как ID, не как URL медиадорожек.
- Прямые ссылки на MP4 и HLS VOD (`.m3u8`) — `<video>`, нативный HLS или `hls.js`. Принимаем HTTPS, а для локальной разработки также HTTP на loopback. Из произвольных страниц потоки не извлекаем, сервер не запрашивает URL источника. Синхронизацию live-потоков, DRM, трансляцию вкладки, TURN, нативные приложения и хранение между рестартами не включаем.
- Ведущий меняет видео, включает воспроизведение, ставит на паузу и перематывает. Зритель нажимает «Смотреть», получает актуальную позицию при входе и восстанавливает синхронизацию при переподключении. Приглашение не даёт прав ведущего. Для скорости/перемотки комнаты используют отдельные общие кнопки, а не локальные кнопки плеера.
- Один процесс Rust/Axum раздаёт собранный Vite-клиент, обслуживает HTTP и WebSocket. Caddy завершает TLS в Docker Compose. Комнаты в памяти, неактивные закрываются.

## Параллельные подзадачи

1. **Сервер (`server/`)** — разбор ссылок, создание и авторизация комнат, состояние и WebSocket, статические файлы, тест авторизации и состояния при позднем входе.
2. **Клиент (`web/`)** — создание комнаты, плееры, приглашение, управление и переподключение; отзывчивая страница и понятные ошибки.
3. **Деплой (корень)** — Dockerfile, Compose, Caddy, `.gitignore`, `.dockerignore`, инструкция локального и VPS-запуска.

Границы в коде: разбор источника и расчёт состояния комнаты не зависят от WebSocket; на клиенте общий контроллер воспроизведения работает через адаптеры YouTube и HTMLVideoElement. Тесты проверяют наблюдаемые действия участников, не добавляя особых путей для тестовых роликов.

Интеграция: собрать обе части, запустить приложение, открыть две реальные вкладки, создать комнату, войти по ссылке, проверить play/pause/seek, поздний вход, права и мобильный viewport. Проверить YouTube, MP4 и HLS; физические устройства и внешнюю сеть отметить отдельно, если они недоступны.

## Контракт

Сервер слушает `BIND_ADDR` (по умолчанию `127.0.0.1:8080`), сайт из `STATIC_DIR` (по умолчанию `web/dist` относительно корня), `GET /api/health` возвращает `200`. SPA использует `/` (создать) и `/r/{roomId}` (войти); браузер хранит host-токен в `sessionStorage`, в ссылке зрителя его нет. Vite проксирует весь `/api` на `http://127.0.0.1:8080` с поддержкой WS.

- `POST /api/rooms` принимает `{ "url": "…" }`. Успех `201`: `{ "roomId": "…", "hostToken": "…" }`. Ошибки валидации/вместимости: HTTP `4xx`, по возможности `{ "code": "…", "message": "…" }`. ID комнаты — случайная способность входа; host-токен — отдельный секрет.
- `GET /api/rooms/{roomId}/ws`: после подключения клиент посылает `{ "type": "join", "hostToken": "…" }`, зритель опускает `hostToken`. Сервер отвечает `{ "type": "joined", "role": "host" | "viewer", "state": State, "serverNowMs": number }`. Неизвестная комната или неверный host-токен: отправить сообщение `error`, затем закрыть соединение.
- Команды ведущего: `{ "type": "load", "url": "…" }`, `{ "type": "play" }`, `{ "type": "pause" }`, `{ "type": "seek", "positionSec": number }`. `load` меняет источник и сбрасывает позицию в 0 и ставит на паузу; `seek` сохраняет состояние паузы. Каждую принятую команду, включая эхо ведущему, сервер рассылает как `{ "type": "state", "state": State, "serverNowMs": number }`.
- Любой участник может послать `{ "type": "ping", "clientNowMs": number }`; ответ `{ "type": "pong", "clientNowMs": number, "serverNowMs": number }`. На клиенте рассчитываем позицию от `updatedAtMs`, используя оценку серверного времени. Ошибка: `{ "type": "error", "code": "room_not_found" | "invalid_host_token" | "invalid_source" | "forbidden" | "invalid_message", "message": "…" }`.
- `State`: `{ "source": { "type": "youtube", "videoId": "…" } | { "type": "mp4" | "hls", "url": "…" }, "paused": boolean, "positionSec": number, "updatedAtMs": number, "revision": number }`. `positionSec` — позиция на `updatedAtMs` (Unix ms), пока играет, позиция растёт на прошедшее время. `revision` растёт при командах, чтобы не применять старые ответы.

## Интеграционная проверка

- Docker Compose: образ собран, Caddy раздаёт SPA; создание комнаты и вход по WebSocket работают. Проверен и локальный прокси Vite.
- Две вкладки Chromium: приглашение, роли, воспроизведение, пауза и перемотка для реальных MP4, HLS и встроенного YouTube. Зритель после отключения сети получил новую позицию комнаты. Подключение зрителя после перемотки и запрет команд зрителя проверены также через WebSocket.
- Viewport 390 px: у зрителя нет горизонтальной прокрутки и общих элементов управления. WebKit воспроизвёл HLS; YouTube IFrame API в этом окружении WebKit не загрузился. Физические телефоны, запасной путь `hls.js` и публичный сертификат Caddy не проверены.
